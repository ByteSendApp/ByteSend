title: Reverse Proxy Setup
description: "Configure Nginx or Traefik as a reverse proxy in front of the ByteSend SMTP Server."
---

A reverse proxy sits in front of the SMTP server and handles TLS termination. This lets you run the ByteSend SMTP Server with `SMTP_TLS_MODE=none` (plain TCP internally) while still serving encrypted connections to clients.

**When to use a reverse proxy:**
- You already run nginx or Traefik on the host and want a single place to manage certificates
- You need to share the server with other services
- The SMTP process runs as a non-root user and cannot bind to privileged ports (25, 465, 587) directly

**When to skip it:**
- You want the simplest possible setup: use `SMTP_TLS_MODE=manual` with certbot instead. See [Certificate Setup](./certificates).

---

## Nginx

Nginx proxies raw TCP (SMTP) via its `stream` module. Each port requires its own `server` block.

<Note>The `stream` module is separate from the `http` module. Ensure your nginx build includes it (`nginx -V 2>&1 | grep stream`), and place the `stream {}` block at the top level of `nginx.conf`, **not** inside `http {}`.</Note>

### Port 587: Submission with STARTTLS

The most common port for application/client email sending. Nginx terminates TLS; the backend receives plain TCP on `127.0.0.1:587` with `SMTP_TLS_MODE=none`.

```nginx
stream {
  upstream smtp_submission {
    server 127.0.0.1:587;
  }

  server {
    listen 587 ssl;
    proxy_pass smtp_submission;

    ssl_certificate     /etc/letsencrypt/live/smtp.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/smtp.example.com/privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;
  }
}
```

### Port 465: Implicit TLS (SMTPS)

Used by clients that require an SSL-wrapped connection from the start (no STARTTLS negotiation). Add a second `server` block in the same `stream {}` context:

```nginx
stream {
  upstream smtp_submission {
    server 127.0.0.1:587;
  }

  upstream smtp_smtps {
    server 127.0.0.1:465;
  }

  # Port 587: STARTTLS
  server {
    listen 587 ssl;
    proxy_pass smtp_submission;

    ssl_certificate     /etc/letsencrypt/live/smtp.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/smtp.example.com/privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;
  }

  # Port 465: Implicit TLS
  server {
    listen 465 ssl;
    proxy_pass smtp_smtps;

    ssl_certificate     /etc/letsencrypt/live/smtp.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/smtp.example.com/privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;
  }
}
```

### Port 25: MTA (Plain / Inter-server)

Port 25 is used by other mail servers (MX delivery) and typically does **not** need TLS termination at the proxy, so pass it straight through. If you do want nginx to sit in front, use a plain TCP proxy without SSL:

```nginx
stream {
  upstream smtp_mta {
    server 127.0.0.1:25;
  }

  # Port 25: plain passthrough (no TLS termination)
  server {
    listen 25;
    proxy_pass smtp_mta;
  }
}
```

<Note>Port 25 is frequently blocked by cloud providers and ISPs. Check whether your host allows outbound/inbound traffic on port 25 before relying on it.</Note>

### Which ports do you need?

| Use case | Port(s) to expose |
|---|---|
| App or client sending email | 587 (recommended), 465 optional |
| Receiving mail from other servers (MX) | 25 |
| All of the above | 25, 465, 587 |

## Traefik (TCP Router)

Traefik routes TCP connections based on entry points. Define one entry point per SMTP port in your static config, then map them to the SMTP container via a TCP router.

### Static configuration (`traefik.yml`)

```yaml
entryPoints:
  smtp-mta:
    address: ":25"
  smtp-smtps:
    address: ":465"
  smtp-submission:
    address: ":587"
```

### Dynamic configuration

```yaml
tcp:
  routers:
    smtp-mta:
      entryPoints:
        - smtp-mta        # :25
      rule: HostSNI(`*`)
      service: smtp-backend

    smtp-smtps:
      entryPoints:
        - smtp-smtps      # :465
      rule: HostSNI(`smtp.example.com`)
      tls:
        passthrough: false
      service: smtp-backend

    smtp-submission:
      entryPoints:
        - smtp-submission  # :587
      rule: HostSNI(`smtp.example.com`)
      tls:
        passthrough: false
      service: smtp-backend

  services:
    smtp-backend:
      loadBalancer:
        servers:
          - address: smtp-container:587
```

<Note>Set `passthrough: false` on TLS routers so Traefik terminates TLS and forwards plain TCP to the container. Set `passthrough: true` if you want Traefik to forward encrypted traffic directly and have the SMTP server handle TLS (`SMTP_TLS_MODE=manual`).</Note>
