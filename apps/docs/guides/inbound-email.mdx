ByteSend can receive email as well as send it. Use it for support inboxes, reply handling ("reply to this email to comment"), parsing invoices or anything else your app needs to read.

Received mail is:

- sent to your app as an `email.received` [webhook](/guides/webhooks),
- available from the API at `GET /v1/inbound/emails`,
- shown on the **Inbox** page in the dashboard, and
- optionally forwarded to another mailbox.

Messages and attachments are kept for **30 days**, then deleted.

## Your hosted address

Every team gets an address that works straight away, with no DNS changes. You'll find it under **Inbox → Addresses**, for example:

```
acme@in.bytesend.cloud
```

Anything after a `+` still reaches you, so you can tell senders apart: `acme+orders@in.bytesend.cloud`, `acme+ticket-4821@in.bytesend.cloud`.

## Receiving on your own domain

Most teams receive on a **subdomain** of a domain they already send from, such as `reply.acme.com`. Only that subdomain's mail comes to ByteSend, so your normal mailboxes on `acme.com` (Google Workspace, Microsoft 365 and so on) keep working. You can also [receive on the domain itself](#receiving-on-the-domain-itself).

<Steps>
  <Step title="Pick a subdomain">
    Go to **Inbox → Addresses**, choose the domain, type a subdomain (for example `reply`) and select **Set up**. The domain must already be verified for sending.
  </Step>
  <Step title="Add the DNS records">
    Add the MX record shown, for example:

    | Type | Name | Value | Priority |
    | --- | --- | --- | --- |
    | MX | `reply` | `inbound-smtp.us-east-1.amazonaws.com` | 10 |

    If your domain sends from a region that can't receive mail, you'll also see a TXT record for a DKIM key. Add that too.
  </Step>
  <Step title="Check DNS">
    Select **Check DNS**. Once the records are found, the status changes to **Receiving** and mail to `anything@reply.acme.com` arrives in your inbox.
  </Step>
</Steps>

### Receiving on the domain itself

You can also receive at the domain itself, like `hey@acme.com`. Choose **The domain itself** instead of a subdomain, then point the domain's MX record at the value shown:

| Type | Name | Value | Priority |
| --- | --- | --- | --- |
| MX | `@` | `inbound-smtp.us-east-1.amazonaws.com` | 10 |

<Warning>
  A domain has one set of MX records, so this sends **all** mail for the domain to ByteSend. If you use Google Workspace, Microsoft 365 or another mailbox on the domain, those mailboxes stop getting new mail. ByteSend shows where the domain's mail goes today and asks you to confirm before switching. To keep your mailboxes, use a subdomain instead, or add [forwarding rules](#forwarding) for the addresses that should still reach a person.
</Warning>

## The `email.received` webhook

Add a webhook and choose the **email.received** event (under *Inbound events*). Each message is posted as JSON:

```json
{
  "id": "call_abc123",
  "type": "email.received",
  "version": "2026-01-18",
  "createdAt": "2026-10-21T09:41:13.000Z",
  "teamId": 123,
  "data": {
    "id": "inb_4f1c2a9e8d7b6a5c4f3e2d1c",
    "recipient": "support@reply.acme.com",
    "from": "jane@example.com",
    "fromName": "Jane Doe",
    "to": ["support@reply.acme.com"],
    "cc": [],
    "replyTo": [],
    "subject": "Where is my order?",
    "text": "Hi, my order hasn't arrived yet...",
    "html": "<p>Hi, my order hasn't arrived yet...</p>",
    "messageId": "<CAB8x...@mail.gmail.com>",
    "inReplyTo": "<0100018f...@us-east-1.amazonses.com>",
    "inReplyToEmailId": "cm4x9...",
    "attachments": [
      {
        "id": "att_9b8c7d6e5f4a3b2c1d0e9f8a",
        "filename": "receipt.pdf",
        "contentType": "application/pdf",
        "size": 48213,
        "url": "https://bytesend.cloud/api/inbound/attachments/inb_.../att_...?expires=...&sig=..."
      }
    ],
    "authentication": { "spf": "pass", "dkim": "pass", "dmarc": "pass", "spam": "pass", "virus": "pass" },
    "domainId": 12,
    "receivedAt": "2026-10-21T09:41:12.000Z"
  }
}
```

- **Replies:** when someone replies to an email you sent through ByteSend, `inReplyToEmailId` is the id of your original email, so you can thread the conversation.
- **Attachments:** `url` downloads the file and works for **one hour**. Download what you need when the webhook arrives, or fetch the email again from the API for a fresh link.
- **Authentication:** `spf`, `dkim` and `dmarc` say whether the sender is who they claim to be. Be careful acting on mail where these are `fail`. Messages with a virus are kept but never forwarded.
- Verify the webhook's signature as described in [Webhooks](/guides/webhooks#signature-verification).

With the TypeScript SDK (`bytesend-js` 0.2 or later), the event is verified and typed for you:

```ts
import { ByteSend } from "bytesend-js";

const webhooks = new ByteSend("bs_...").webhooks(process.env.BYTESEND_WEBHOOK_SECRET!);

export async function POST(request: Request) {
  const event = webhooks.constructEvent(await request.text(), { headers: request.headers });

  if (event.type === "email.received" && event.data.inReplyToEmailId) {
    await comments.create({ thread: event.data.inReplyToEmailId, body: event.data.text });
  }

  return new Response("ok");
}
```

## Fetching received mail from the API

<CodeGroup>

```ts Node.js
const { data } = await bytesend.inbound.list({ limit: 20 });
```

```bash cURL
curl https://bytesend.cloud/api/v1/inbound/emails?limit=20 \
  -H "Authorization: Bearer bs_..."
```

</CodeGroup>

Filter with `recipient`, `since` (an ISO 8601 time) and `page`. Get one message, including its text, HTML and attachment links:

<CodeGroup>

```ts Node.js
const { data: email } = await bytesend.inbound.get("inb_4f1c2a9e8d7b6a5c4f3e2d1c");

for (const attachment of email!.attachments) {
  const file = await bytesend.inbound.downloadAttachment(attachment);
}
```

```bash cURL
curl https://bytesend.cloud/api/v1/inbound/emails/inb_4f1c2a9e8d7b6a5c4f3e2d1c \
  -H "Authorization: Bearer bs_..."
```

</CodeGroup>

API keys limited to one domain only see mail received on that domain.

## Forwarding

Under **Inbox → Forwarding**, forward mail to another address. A rule matches:

- a full address (`support@reply.acme.com`),
- the part before the `@` on any of your addresses (`support`), or
- everything (`*`).

Forwarded mail is sent from `forwarding@` your verified domain, with the original sender as the reply-to address, so replying from your mailbox goes to the right person. Forwarded mail counts toward your sending.

### Reply as your address from Gmail or Outlook

Forward an address like `hey@acme.com` to your own mailbox, then reply *as* that address through ByteSend's SMTP relay, signed with your domain's DKIM:

1. Add a forwarding rule from `hey` to your Gmail or Outlook address.
2. In Gmail, open **Settings → Accounts → Send mail as → Add another email address**. In Outlook, add it as a send-from address.
3. Enter `hey@acme.com`, then the SMTP server `smtp.bytesend.cloud`, port `587` with TLS, your SMTP username from **Settings → SMTP**, and an API key as the password.

This suits a few personal addresses. ByteSend doesn't host mailboxes, so there's no IMAP access, and received mail is kept for 30 days.

## Self-hosting

Receiving uses Amazon SES, which only receives mail in some AWS regions (including `us-east-1`, `us-west-2` and `eu-west-1`). To turn it on:

1. Create an S3 bucket in that region, with a bucket policy that lets `ses.amazonaws.com` put objects in it.
2. Create an SNS topic in the same region and subscribe `https://<your-app>/api/inbound_callback` to it over HTTPS.
3. Set `INBOUND_REGION`, `INBOUND_S3_BUCKET` and `INBOUND_SNS_TOPIC_ARN`. Optionally set `INBOUND_HOSTED_DOMAIN` to give every team an address on a domain you own, and point that domain's MX at `inbound-smtp.<region>.amazonaws.com`.
4. In **Admin → SES regions**, select **Create receiving rule**.

For local development, `pnpm dx:up` and `pnpm dev:local` already work: open the emulator at `http://localhost:5350` and use **Send mail to ByteSend**.
