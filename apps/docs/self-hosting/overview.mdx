ByteSend is fully self-hostable. This guide covers two deployment paths:

- **[Docker (recommended)](#docker-deployment)**: spin up the entire stack with a single `docker compose` command
- **[Manual / bare-metal](#manual-deployment)**: install directly on a Linux server using Node.js and pnpm

If you have questions, join [#self-host](https://discord.gg/C2Q4GHXKQA) on Discord.

---

## Prerequisites

Both methods require:

- A server running Ubuntu 22.04 or later (or similar Debian-based distro)
- A domain name pointing to your server's IP
- An [AWS account](https://aws.amazon.com) with SES access (for email delivery)

---

## Docker Deployment

Docker is the fastest way to get ByteSend running. The `docker/prod/compose.yml` file in the repository pulls pre-built images from DockerHub and starts the web app, PostgreSQL, Redis, MinIO (S3-compatible storage), and the SMTP relay together.

### 1. Install Docker

```bash
# Install Docker Engine
curl -fsSL https://get.docker.com | sh

# Add your user to the docker group
sudo usermod -aG docker $USER
newgrp docker
```

### 2. Clone the repository

```bash
git clone https://github.com/ByteSendApp/ByteSend.git
cd ByteSend
```

### 3. Configure environment variables

```bash
cp docker/prod/.env.example docker/prod/.env
nano docker/prod/.env
```

At minimum, set the following variables:

```bash
# Application
NEXTAUTH_URL=https://your-domain.com
NEXTAUTH_SECRET=<run: openssl rand -base64 32>

# Database (managed by compose: change password)
POSTGRES_PASSWORD=<strong-password>
DATABASE_URL=postgresql://bytesend:<strong-password>@postgres:5432/bytesend

# Redis (managed by compose)
REDIS_URL=redis://redis:6379

# AWS SES
AWS_ACCESS_KEY=<your-access-key-id>
AWS_SECRET_KEY=<your-secret-access-key>
AWS_DEFAULT_REGION=eu-west-1

# GitHub OAuth (optional: enables social sign-in)
GITHUB_ID=
GITHUB_SECRET=

# Stripe (optional: enables billing)
STRIPE_SECRET_KEY=
STRIPE_WEBHOOK_SECRET=
```

### 4. Start the stack

```bash
docker compose -f docker/prod/compose.yml --env-file docker/prod/.env up -d
```

This pulls the latest images from DockerHub and starts:

| Container | Image | Description |
|---|---|---|
| `web` | `bytesend/bytesend:latest` | ByteSend Next.js application (port 3000) |
| `postgres` | `postgres:16` | PostgreSQL 16 database |
| `redis` | `redis:7` | Redis 7 |
| `minio` | `minio/minio:latest` | S3-compatible object storage |
| `smtp` | `bytesend/smtp-proxy:latest` | SMTP relay server |

### 5. Run database migrations

```bash
docker compose -f docker/prod/compose.yml --env-file docker/prod/.env exec web pnpm db:migrate-deploy
```

### 6. Verify

```bash
docker compose -f docker/prod/compose.yml --env-file docker/prod/.env ps
docker compose -f docker/prod/compose.yml --env-file docker/prod/.env logs -f web
```

The app is now accessible at **http://your-server-ip:3000**.

<Note>Port 3000 should not be exposed directly in production. Set up a reverse proxy (nginx or Traefik) in front of it and configure HTTPS. See [Reverse Proxy Setup](./reverse-proxy) for the SMTP server guide. The same nginx patterns apply.</Note>

## Manual Deployment

If you prefer not to use Docker, you can install ByteSend directly on the host.

### 1. Install Node.js and pnpm

```bash
# Install Node.js 20 via nvm
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash
source ~/.bashrc
nvm install 20
nvm use 20

# Enable pnpm via corepack
corepack enable
```

### 2. Install PostgreSQL 16

```bash
sudo apt install -y postgresql postgresql-contrib

# Create a database and user
sudo -u postgres psql <<'SQL'
CREATE USER bytesend WITH PASSWORD 'changeme';
CREATE DATABASE bytesend OWNER bytesend;
SQL
```

### 3. Install Redis 7

```bash
sudo apt install -y redis-server
sudo systemctl enable redis-server
sudo systemctl start redis-server
```

### 4. Clone and install

```bash
git clone https://github.com/ByteSendApp/ByteSend.git
cd bytesend
pnpm install
```

### 5. Configure environment variables

```bash
cp .env.example .env
nano .env
```

Set local connection strings and fill in all required values:

```bash
DATABASE_URL=postgresql://bytesend:changeme@127.0.0.1:5432/bytesend
REDIS_URL=redis://127.0.0.1:6379
NEXTAUTH_URL=https://your-domain.com
NEXTAUTH_SECRET=<run: openssl rand -base64 32>
AWS_ACCESS_KEY=<your-access-key-id>
AWS_SECRET_KEY=<your-secret-access-key>
AWS_DEFAULT_REGION=eu-west-1
FROM_EMAIL=noreply@your-domain.com
```

Then add OAuth credentials for any providers you want (see step 4 in the Docker section for setup links):

```bash
# At least one OAuth provider recommended (all optional)
GITHUB_ID=
GITHUB_SECRET=
DISCORD_CLIENT_ID=
DISCORD_CLIENT_SECRET=
GOOGLE_CLIENT_ID=
GOOGLE_CLIENT_SECRET=
```

Create the symlink that Next.js expects:

```bash
ln -s ../../.env apps/web/.env
```

### 6. Build the application

```bash
pnpm build:web
```

### 7. Run database migrations

```bash
pnpm db:migrate-deploy
```

### 8. Start the application

```bash
pnpm --filter=web start
```

The app will start on port 3000.

### Running as a systemd service

To keep ByteSend running after reboots, create a systemd unit:

```bash
sudo tee /etc/systemd/system/bytesend.service > /dev/null <<EOF
[Unit]
Description=ByteSend Web Application
After=network.target postgresql.service redis.service

[Service]
Type=simple
User=$USER
WorkingDirectory=/home/$USER/bytesend
ExecStart=/usr/bin/pnpm --filter=web start
Restart=on-failure
RestartSec=5
EnvironmentFile=/home/$USER/bytesend/.env

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable bytesend
sudo systemctl start bytesend
```

Check the status:

```bash
sudo systemctl status bytesend
sudo journalctl -u bytesend -f
```

## Environment Variable Reference

| Variable | Required | Description |
|---|---|---|
| `DATABASE_URL` | Yes | PostgreSQL connection string |
| `REDIS_URL` | Yes | Redis connection string |
| `NEXTAUTH_URL` | Yes | Public URL of the app |
| `NEXTAUTH_SECRET` | Yes | Random session signing secret |
| `AWS_ACCESS_KEY` | Yes | AWS access key ID |
| `AWS_SECRET_KEY` | Yes | AWS secret access key |
| `AWS_DEFAULT_REGION` | Yes | AWS region (e.g. `eu-west-1`) |
| `FROM_EMAIL` | Yes | From address for account emails |
| `GITHUB_ID` / `GITHUB_SECRET` | No | GitHub OAuth credentials |
| `DISCORD_CLIENT_ID` / `DISCORD_CLIENT_SECRET` | No | Discord OAuth credentials |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | No | Google OAuth credentials |
| `S3_COMPATIBLE_*` | No | S3-compatible storage (defaults to bundled MinIO) |
| `S3_COMPATIBLE_REGION` | No | Bucket region. AWS S3 needs the real region (e.g. `us-east-1`); R2 and MinIO use the default `auto` |
| `SMTP_HOST` / `SMTP_USER` | No | External SMTP relay for account emails |
| `ADMIN_EMAIL` | No | Grants admin panel access to this address |
| `DISCORD_WEBHOOK_URL` | No | Discord webhook for platform alerts (signups, blocked teams, blocklisted domains) |
| `SPAMHAUS_DQS_KEY` | No | Spamhaus Data Query Service key for reliable blocklist and link-reputation checks |
| `API_RATE_LIMIT` | No | API requests per second per key (default `1`) |
| `AUTH_EMAIL_RATE_LIMIT` | No | Magic-link emails per minute (default `5`) |
